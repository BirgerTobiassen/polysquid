Polysquid

A Python-based manager for deploying and operating multiple isolated Squid proxy instances — declared in YAML, automated by systemd, containerised with Docker.

Python 3 Squid Docker systemd YAML Linux
2
The problem

Managing Squid at Scale Is Hard

Manual complexity

  • Each Squid instance needs its own config, service file, and log rotation
  • Configs drift between servers over time
  • No standard way to schedule proxy uptime windows

Operational risk

  • Ad-hoc changes bypass review — configs break silently
  • No audit trail for whitelist changes
  • Shared config files accidentally create allow-all policies
3
The solution

One YAML File — Many Proxy Services

Polysquid reads services.yaml and fully reconciles the desired state: containers, systemd units, ACLs, timers, and log rotation — every reconcile run.

Declarative

Define services in YAML. Polysquid figures out what needs to change.

Isolated

Each service runs in its own Docker container with dedicated config, logs, and cache.

Automated

Git-triggered reconciliation every 5 minutes. Zero manual intervention after initial deploy.

Configuration

Declarative YAML Services

services:
  # Scheduled corporate proxy — weekdays 8am–6pm, TLS, IP-restricted
  - name: "Corporate Proxy"
    port: 3128
    use_tls: true
    enabled: true

      string: "Mon..Fri 08:00..18:00"

      - 192.168.1.0/24

        - office_sites

Access control

Flexible, Fail-Closed Domain Filtering

  • Inline lists — literal domains in YAML
  • Shared lists — reusable named lists, referenced by multiple services
  • EDL (External Data Lists) — fetched from a URL at every reconcile
  • Fail-closed — if whitelists: key is present, traffic is denied by default, even if the resolved list is empty
  • Overlap-safe — child domains automatically pruned when parent is already listed
Deny-by-default EDLManager compatible Subdomain matching 
shared:
  lists:
    office_sites:
      - .github.com
      - .npm.org
    media:
      - .nrk.no
      - .tv2.no

# Service uses multiple sources:
whitelists:
  list:
    - .internal.corp
  shared:
    - office_sites
  edl:
    - https://example.com/list.txt

Scheduling

systemd-Native Scheduling

Services with on_calendar are timer-managed and never fall through to always-on — even if the calendar resolves empty.

  • Start timer fires at window open
  • Stop timer fires at window close
  • Boot reconciler starts service if boot time is inside an active window
  • Shared calendar entries — define once, reference everywhere
# Structured on_calendar
on_calendar:
  string: "Mon..Fri 08:00..18:00"

# ...or reference a shared calendar
on_calendar:
  shared: work_hours

shared:
  calendars:
    work_hours:
      "Mon..Fri 08:00..18:00"
    off_hours:
      "Mon..Fri 18:00..08:00"

Self-service

End-User Access Portal

The optional self-service component lets end users request proxy access without admin involvement.

  • Flask web app behind an nginx TLS reverse proxy
  • User specifies port + justification; request saved as a YAML file
  • systemd path unit detects new request file and triggers immediate reconciliation
  • IP-subnet gating — portal only reachable from allowed networks (outside-subnet.html fallback)
  • Admin reviews request files via whitelist-manager.py CLI helper

Components

Flask app · nginx · polysquid-self-service.service · polysquid-path.service

Security

TLS everywhere · subnet firewall · read-only request files · no root in webapp container

9
Security & reliability

Built-In Safeguards

Fail-Closed ACLs

Declaring whitelists: triggers deny-by-default — no misconfigured allow-all is possible.

Timer Isolation

Calendar-managed services cannot become always-on even if the calendar entry is invalid.

Domain Normalisation

Labels validated, trailing dots stripped, wildcard *. mapped to Squid's . prefix. Squid config never receives malformed entries.

Overlap Pruning

Child domains removed when a parent already covers them — prevents Squid fatal errors on overlapping ACL entries.

Chunked ACL Output

Large whitelists split into 200-entry acl whitelist dstdomain lines — avoids Squid line-length parse failures.

EDL Resilience

EDL fetch failures log an error and leave the service deny-by-default. Cached per-reconcile to avoid redundant requests.

Operations

Fully Automated Lifecycle

  • Install once — sudo ./install.sh sets everything up
  • Git-driven deploys — timer polls Git every 5 min; changed services.yaml triggers trusted executor
  • Zero-downtime updates — only affected services are restarted
  • Log rotation — per-service logrotate configs, daily, 30-day retention
  • Boot recovery — reconcile on boot restores correct state for all windowed services
  • Manual override — sudo python3 polysquid.py --verbose anytime
# View all managed units
systemctl list-units "polysquid-*"

# Check update timer
systemctl status polysquid-git-update.timer

# View generated Squid config
cat /opt/polysquid/polysquid-services/ \
    <service>/conf/squid.conf

# Tail container logs
docker logs polysquid_<service> -f

Technical stack

Technology Choices

Runtime

Python 3 · PyYAML · urllib (stdlib only — no extra HTTP deps)

Proxy engine

Squid 5+ in Docker (Debian 12, squid-openssl) — avoids GnuTLS chain-delivery bugs on TLS listeners

Init system

systemd — services, timers, path units, and logrotate all generated by the reconciler

Self-service

Flask · nginx (TLS reverse proxy) · subnet-gated HTML fallback

Secrets / Certs

Let's Encrypt (HTTP-01 or DNS-01) · shared cert path /etc/polysquid/certs/

Config control

Git repository — services.yaml is the single source of truth, version-controlled
